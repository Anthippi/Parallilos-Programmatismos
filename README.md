## Επισκόπηση

Αυτό το αποθετήριο περιέχει μια ολοκληρωμένη σουίτα υλοποιήσεων και μετρήσεων απόδοσης (benchmarks) **Παράλληλης Αριθμητικής Ολοκλήρωσης** με χρήση του **Τραπεζοειδούς Κανόνα**. Αναπτύχθηκε στο πλαίσιο του μαθήματος *Παράλληλος Προγραμματισμός (2025–2026)* στο **Οικονομικό Πανεπιστήμιο Αθηνών (ΟΠΑ)**, Τμήμα Πληροφορικής.

Το project εξερευνά αρχιτεκτονικές παράλληλου υπολογισμού σε πολυπύρηνες CPU και μαζικές GPU μέσα από τρία βασικά μοντέλα παράλληλου προγραμματισμού:
1. **POSIX Threads (Pthreads)** — Πολυνηματικός προγραμματισμός κοινόχρηστης μνήμης με χειροκίνητο συγχρονισμό, στατικό διαμοιρασμό εργασίας, κυκλική δρομολόγηση με άλματα και ουρές εργασιών (thread-safe).
2. **OpenMP** — Παραλληλοποίηση βασισμένη σε οδηγίες του μεταγλωττιστή (compiler directives), καλύπτοντας static/dynamic/guided δρομολόγηση βρόχων, αναγωγές (reductions), και ρητή ασύγχρονη δημιουργία εργασιών (γραμμική & αναδρομική διάσπαση).
3. **NVIDIA CUDA** — Υψηλής απόδοσης επιτάχυνση στην GPU, διερεύνηση βελτιστοποιήσεων στην ιεραρχία μνήμης (Global, Registers, Shared Memory με Parallel Tree Reduction), grid-stride loops, και μείωση του φαινομένου της απόκλισης (warp divergence).

## Μαθηματικό Υπόβαθρο

Η αριθμητική προσέγγιση του ορισμένου ολοκληρώματος $\int_{a}^{b} f(x) dx$ υπολογίζεται μέσω του **Τραπεζοειδούς Κανόνα**:

$$\int_{a}^{b} f(x) dx \approx \frac{h}{2} \left[ f(a) + f(b) + 2 \sum_{i=1}^{n-1} f(a + i \cdot h) \right], \quad \text{όπου } h = \frac{b - a}{n}$$

Για την αξιολόγηση της ισοκατανομής φόρτου και των χαρακτηριστικών εκτέλεσης υπό διαφορετικές υπολογιστικές απαιτήσεις, ελέγχονται δύο σενάρια:
* **Ομαλός Υπολογιστικός Φόρτος (Regular Workload):** $f(x) = x^2$ στο διάστημα $[0, 10]$ (ομοιόμορφος υπολογιστικός φόρτος ανά επανάληψη).
* **Ακανόνιστος / Δυναμικός Φόρτος (Irregular Workload):** Συνθετικές τριγωνομετρικές συναρτήσεις $f(x)$ με μεταβλητό βάθος επαναλήψεων $g(x) = \lfloor |\sin(x \cdot 123.45)| \times 600 \rfloor$, οι οποίες δημιουργούν προβλέψιμες ή τυχαίες υπολογιστικές εξάρσεις (προσομοιώνοντας έντονη ανισοκατανομή φόρτου και warp divergence).

## Βασικές Υλοποιήσεις & Προσεγγίσεις

### Εργασία 1: POSIX Threads (Pthreads)
* **Μέρος Α1 — Στατικός Διαμοιρασμός με ενημερώσεις Mutex:** Στατικός διαμοιρασμός σε ισομεγέθη, συνεχόμενα τμήματα (`N / num_threads`) περιοδική συσσώρευση σε κρίσιμη περιοχή με προοδευτική εμφάνιση του αποτελέσματος χρησιμοποιώντας `pthread_mutex_t`.
* **Μέρος Α2 — Στατικός Διαμοιρασμός με Τοπική Συσσώρευση:** Απομονωμένοι τοπικοί πίνακες ανά νήμα για την αποθήκευση μερικών αθροισμάτων μηδενικός ανταγωνισμός (contention) για mutex κατά την εκτέλεση και τελική συσσώρευση στο κύριο νήμα (`pthread_join`).
* **Μέρος Β — Κυκλική Δρομολόγηση με Άλματα (Cyclic/Jump Scheduling):** Βήμα βρόχου με άλματα (`i += num_threads`) που εξασφαλίζει δίκαιη κατανομή ελαφριών και βαριών υπολογιστικά επαναλήψεων.
* **Μέρος Γ — Δυναμική Ουρά Εργασιών:** Κεντρικός μετρητής εργασιών προστατευμένος με mutex τα νήματα αντλούν δυναμικά πακέτα σταθερού μεγέθους (`CHUNK_SIZE`) για την αντιμετώπιση της ανισοκατανομής φόρτου.

### Εργασία 2: Παραλληλοποίηση με OpenMP
* **Μέρος Α — Διαμοιρασμός Εργασίας σε Βρόχους (Work-Sharing For Loops):** Σύγκριση μεταξύ `#pragma omp parallel for reduction(+:sum)` και τοπικής συσσώρευσης ανά νήμα με χρήση `#pragma omp atomic`.
* **Μέρος Β — Πολιτικές Δρομολόγησης Βρόχων:** Μελέτη απόδοσης των `schedule(static)`, `schedule(dynamic, chunk)`, και `schedule(guided, chunk)` μεταβάλλοντας τα μεγέθη των πακέτων (chunk sizes από 1 έως 100,000,000).
* **Μέρος Γ — Ρητά Tasks (Explicit Tasks) στο OpenMP:**
  * *Γραμμική Δημιουργία Tasks:* Ένα μοναδικό κύριο νήμα (single master thread) πακετάρει κομμάτια επαναλήψεων μέσω του `#pragma omp task`.
  * *Αναδρομική Διάσπαση (Divide-and-Conquer):* Δυαδική διάσπαση του υποδιαστήματος με `#pragma omp taskwait` και ρητό κατώφλι τερματισμού αναδρομής ($N \le 1000$) για την αποφυγή του διαχειριστικού κόστους παραγωγής εργασιών.

### Εργασία 3: Επιτάχυνση GPU με NVIDIA CUDA
* **Αξιολόγηση Ιεραρχίας Μνήμης (Memory Hierarchy Benchmarking):**
  * *Naïve / Παγκόσμια Μνήμη (Global Memory):* Απευθείας ατομικές προσθέσεις (`atomicAdd`) στην παγκόσμια μνήμη σε κάθε επανάληψη (σημαντικό bottleneck).
  * *Καταχωρητές (Registers) + Grid-Stride Loop:* Συσσώρευση σε τοπικούς καταχωρητές ανά νήμα πριν από μια μοναδική τελική `atomicAdd` στην παγκόσμια μνήμη.
  * *Κοινόχρηστη Μνήμη (Shared Memory) + Parallel Tree Reduction:* Δυναμική δέσμευση κοινόχρηστου πίνακα ανά Block (`sdata[]`), συγχρονισμός εντός του Block με `__syncthreads()`, λογαριθμική αναγωγή (tree reduction) και μία μόνο ατομική εγγραφή ανά Block από το `threadIdx.x == 0`.
* **Ανάλυση Απόκλισης (Warp Divergence):** Αξιολόγηση της υποβάθμισης της απόδοσης όταν τα νήματα εντός ενός warp 32-νημάτων εκτελούν διαφορετικά μονοπάτια κώδικα (branch execution variance) κάτω από ακανόνιστους φόρτους.

## Σύνοψη Αποτελεσμάτων (Benchmarks)

Τα πειράματα διεξήχθησαν σε επεξεργαστή **AMD Ryzen AI 7 350** (8 Cores / 16 Processors) με κάρτα γραφικών **NVIDIA GeForce RTX 5060 Laptop GPU** (26 SMs, Compute Capability 12.0) σε περιβάλλον Windows 11 (MSYS2 MinGW-w64).

### Σύγκριση Επιδόσεων ($N = 100,000,000$, Ομαλή Συνάρτηση $f(x) = x^2$)

| Μοντέλο Προγραμματισμού | Βέλτιστη Στρατηγική / Ρύθμιση | Χρόνος Εκτέλεσης (sec) | Επιτάχυνση (Speedup) |
| :--- | :--- | :---: | :---: |
| **CPU Σειριακά** | Κλασικός σειριακός `for` βρόχος | `0.3630 s` | 1.0x |
| **GPU Σειριακά** | CUDA Kernel `<<<1, 1>>>` | `0.1690 s` | 2.1x |
| **POSIX Threads** | Μέρος Α2: Τοπικός Πίνακας Νημάτων (8 νήματα) | `0.1150 s` | 3.16x |
| **OpenMP** | Work-sharing `reduction(+:sum)` (8 νήματα) | `0.0440 s` | 8.25x |
| **NVIDIA CUDA** | Registers / Shared Memory Tree Reduction | **`0.0072 s`** | **50.41x** |

> **Βασικό Συμπέρασμα:** Οι υλοποιήσεις στο CUDA με Shared Memory / Registers πέτυχαν **επιτάχυνση 50x** σε σχέση με τη σειριακή εκτέλεση (ένα νήμα) και **επιτάχυνση 6x** συγκριτικά με την ταχύτερη πολυπύρηνη CPU υλοποίηση σε OpenMP.

## Οδηγίες Μεταγλώττισης & Εκτέλεσης

### Προαπαιτούμενα
* **Μεταγλωττιστής C/C++:** `gcc` / `g++` (v14+) με υποστήριξη POSIX threads (`-pthread`) και OpenMP (`-fopenmp`).
* **CUDA Toolkit:** NVIDIA CUDA Toolkit 12.x (`nvcc`).

### Ειδικά για Windows (MSYS2 / UCRT64)
Όλα τα πειράματα CPU (Pthreads και OpenMP) σε περιβάλλον Windows εκτελέστηκαν μέσω του **MSYS2**. Για να μεταγλωττίσετε και να τρέξετε τον κώδικα:
1. Εγκαταστήστε το [MSYS2](https://www.msys2.org/).
2. Ανοίξτε το τερματικό **MSYS2 UCRT64** (ή MinGW64).
3. Βεβαιωθείτε ότι έχετε εγκαταστήσει τον μεταγλωττιστή GCC εκτελώντας:
   ```bash
   pacman -S mingw-w64-ucrt-x86_64-gcc
   ```
4. Πλοηγηθείτε στον φάκελο του project και εκτελέστε τις παρακάτω εντολές κανονικά.

### Μεταγλώττιση (Compile) και Εκτέλεση (Run)

#### 1. POSIX Threads (Pthreads)
```bash
# Μεταγλώττιση της υλοποίησης Pthreads (Χωρίς optimization flags βάσει της εκφώνησης)
gcc -Wall -pthread 1_Pthreads/src/partA_static_nolocks.c -o pthreads_sim -lm

# Εκτέλεση προγράμματος
./pthreads_sim
```

#### 2. OpenMP
```bash
# Μεταγλώττιση της υλοποίησης OpenMP
gcc -Wall -fopenmp 2_OpenMP/src/integration_openmp_schedules.c -o openmp_sim -lm

# Ορισμός πλήθους νημάτων και εκτέλεση
export OMP_NUM_THREADS=8
./openmp_sim
```

#### 3. NVIDIA CUDA
```bash
# Μεταγλώττιση του CUDA Kernel χρησιμοποιώντας nvcc
nvcc -O2 3_CUDA/src/integration_cuda.cu -o cuda_sim

# Εκτέλεση της προσομοίωσης στην GPU
./cuda_sim
```
